## 2. Найденные ошибки старого ввода (заменён полностью)

1. Касания ловил `SurfaceView`, который в режиме Fit меньше экрана: касания в чёрных полях терялись, а зона тачпада считалась от размеров экрана → смещение.
2. Прокрутка двумя пальцами: `(int)(-dy/6dp)` за одно событие почти всегда 0 → медленная прокрутка не работала.
3. Тап двумя пальцами давал ПКМ **и** ЛКМ; двойной тап давал **три** клика.
4. Смена пальца (поднят первый) → скачок курсора.
5. Ctrl/Alt/Win + буква отправляли Unicode-символ → горячие клавиши (Ctrl+C и т.п.) не работали.
6. Клавиша `\` ломала JSON (не экранировался обратный слеш).
7. Клавиши только «клик» (без удержания), автоповтора нет.
8. Новое HTTP-соединение на каждое событие, ошибки молча игнорировались; потеря «отпускания» = залипание.
9. Абсолютный режим создавал `mss.MSS()` на **каждое** движение (миллисекунды на событие).
10. Настройки ширины/высоты клавиатуры и прозрачности клавиш не применялись; позиция не настраивалась; анимации закрытия не было.

## 3. Реализация

**Транспорт (новое):** один постоянный chunked `POST /api/input/stream` на том же порту 5000 (новых правил брандмауэра не нужно),
бинарные кадры `u8 тип, u8 флаги, u16 длина` (`modules/input_engine.py` ↔ `PcInputProtocol.java`). TCP_NODELAY,
все накопившиеся кадры уходят одним сегментом, подряд идущие движения/прокрутка сливаются только в хвосте очереди
(порядок событий не меняется). PING раз в секунду, обнаружение «зависшей» записи, автопереподключение с повторной
отправкой удерживаемых клавиш. Если сервер старый (нет `/api/input/info`) — откат на прежние JSON-эндпоинты.
Тело читается из `wsgi.input` напрямую: `request.stream` ограничен `MAX_CONTENT_LENGTH = 1 МБ`.

**Сервер:** `InputSession` (состояние, автоповтор с задержкой/частотой из настроек клавиатуры Windows, сторожевой таймер,
накопление колеса), `SendInputBackend` (VK + аппаратный скан-код через `MapVirtualKeyW`, X1/X2, горизонтальное колесо,
Unicode с суррогатными парами), кэш геометрии мониторов. Старые `/api/mouse`, `/api/keyboard` сохранены.

**Тачпад (`PcTouchpadEngine.java`):** движение (чувствительность, ускорение, субпиксельный остаток), тап = ЛКМ,
двойной тап = двойной клик, тап+движение и долгое нажатие = перетаскивание с удержанием ЛКМ, 2 пальца: тап = ПКМ,
движение = прокрутка (верт./гориз., естественная/обратная), 3 пальца = СКМ. Абсолютный режим: касание по картинке ПК,
тап = клик в точке, ведение = перетаскивание, долгое нажатие = ПКМ.

**Клавиатура (`PcKeyboardLogic.java`, `PcKeyboardView.java`):** EN/RU/UK (включая ё, ї, ґ, є, і, №, ₴), слой символов,
слой Fn (F1–F12, Ctrl+C/V/X/Z/Y/A/S/F, Alt+Tab, Alt+F4, Win+D/E/R/Tab/V, Ctrl+Shift+Esc, Win+Shift+S, громкость/медиа).
Строка Esc, Tab, Home, End, PgUp/PgDn, Ins, Del, PrtSc, стрелки, пробел, Enter, Backspace.
Модификаторы: удержание = настоящий аккорд; тап = на одну клавишу; второй тап = фиксация (Shift = Caps); третий — снять.
Нажатие отправляется при касании, отпускание — при подъёме пальца, мультитач по клавишам.
Режим «Клавиши (игры)» — буквы физическими VK. Системная клавиатура Android не используется.

**Интерфейс (без редизайна):** прежние цвета/кнопки/плеер сохранены. Добавлено:
- «Управление ПК»: круглые кнопки **🖱** (вкл/выкл мыши) и **⌨** (открыть/закрыть клавиатуру) рядом с ⚙ в том же стиле;
  прежние кнопки «Тачпад»/«Клавиатура» в быстром меню работают так же.
- «Демонстрация экрана»: кнопки 🖱 и ⌨ в верхней панели (по умолчанию мышь выключена — поведение просмотра прежнее).
- Настройки тачпада: + ускорение, скорость и направление прокрутки, видимость зоны. Прежний редактор с 8 маркерами и живым превью сохранён.
- Настройки клавиатуры: высота, ширина, положение (также перетаскивание за полоску сверху), прозрачность подложки и клавиш, язык, режим клавиш, вибрация.
- Клавиатура плавно выезжает/уезжает (220/180 мс).
- Кнопки 🖱/⌨ краснеют при обрыве связи ввода.

**Защита от залипания:** отпускание при закрытии клавиатуры, потере фокуса окна (шторка, другое приложение), закрытии плеера,
обрыве соединения (сервер), 3,5 с тишины при удерживаемых клавишах (сервер), выходе сервера (`atexit`).

## 5. Ограничения и замечания

- **Телефон не тестировался** (см. начало).
- Сервер ПК нужно **перезапустить**, чтобы появился `/api/input/stream`; до этого APK работает через старые JSON-эндпоинты.
- Приложения на Tk (и другие, которые распознают горячие клавиши по символу) при кириллической раскладке ПК не реагируют на Ctrl+C — так же, как с физической клавиатурой. Обычные приложения Windows работают по VK при любой раскладке.
- Ctrl+Alt+Del и Win+L через SendInput невозможны (защищённые комбинации Windows), поэтому в слой Fn не добавлены.
- Если сервер запущен без прав администратора, Windows (UIPI) не даст управлять окнами, запущенными от администратора, и экраном UAC.
- К относительному движению Windows применяет свою «скорость указателя».
- Найдено попутно, **не исправлено** (вне задачи): `/api/mic/stream` читает `request.stream`, ограниченный 1 МБ → передача микрофона, вероятно, обрывается примерно через 30 с.
