# Отчёт 15. Лаунчер как центр установки и настройки. Проверка «чистой» установки

Дата: 2026-11-08.

## Цель

Сценарий: скачать ZIP с GitHub → распаковать в любую папку → запустить `Launcher.exe` → пройти мастер → пользоваться.
Без ручного запуска BAT/CMD/PowerShell, без правки JSON и без терминала.

## Как проверялось

1. Чистая установка воспроизведена на этом ПК.
   - Источник: `git archive HEAD`, то есть ровно то, что отдаёт кнопка GitHub «Download ZIP».
   - Распаковано в папку с пробелом и кириллицей в пути: `%TEMP%\PC Control тест\pc-control-main`.
   - Папки `runtime\` и `config.json` в архиве нет. Состояние полностью как у нового пользователя.
2. `Launcher.exe` → `bootstrap_runtime.ps1`:
   - скачал изолированный Python 3.12 с проверкой SHA-256;
   - установил библиотеки за 78 с, код выхода 0;
   - открыл панель.
3. Первый запуск:
   - `config.json` создан автоматически: IP в локальной сети, MAC, адрес Tailscale, случайный ключ доступа;
   - язык определяется по языку интерфейса Windows.
4. Порт 5000 был занят (на нём работает основная копия сервера). Сервер сам перешёл на 5001, сохранил порт и сообщил об этом.
5. Мастер настройки прошёл все 5 шагов автоматически, за 1–2 с (журнал панели: `[SETUP] First-run setup wizard completed; all checks passed`). Скриншот мастера проверен.
6. QR-код, скачивание APK и `/status` по адресу в локальной сети отвечают.
7. Правило брандмауэра создаётся и проверяется.
8. pytest: 199 тестов прошли. Один тест (`git archive` подставляет `build-info.json`) проходит после коммита этого файла.

### Мастер настройки (№ 1)

Шаги мастера:

1. Компоненты — установка с ожиданием результата.
2. Сеть.
3. Сервер — запуск и проверка, что он действительно отвечает.
4. Брандмауэр — объясняет, зачем нужно правило, и ждёт согласия: «Разрешить» или «Пропустить».
5. Доступ по сетевому адресу.

Как он работает:

- Переход к следующему шагу происходит только после проверки предыдущего.
- При сбое мастер останавливается, показывает причину и кнопку «Повторить».
- При первом запуске мастер открывается сам.
- Признак завершения хранится в `config.json` (`setup_completed`).
- Открыть мастер повторно можно кнопкой «Мастер настройки» или по адресу `?wizard=1`.

## Проверка BAT-файлов

Все BAT — тонкие обёртки над теми же функциями панели (`manage_server.py`). Каждое их действие доступно кнопкой в окне программы. Удалять их не стали: на них опираются автозапуск (`start_silent.vbs`) и деинсталлятор.

## Что НЕ проверено (честно)

- **Другой компьютер.** Чистая установка воспроизведена в отдельной папке на этом же ПК. На ПК без интернета, со строгой политикой PowerShell или с антивирусом, блокирующим загрузку Python, поведение не проверялось.
- **Подключение телефона.** Устройства нет. Шаг «Доступ из сети» обращается к сетевому адресу с самого ПК. Он подтверждает, что сервер слушает сеть, но не проходит через Wi-Fi-роутер. Изоляцию клиентов на гостевом Wi-Fi он не обнаружит. Мастер говорит об этом прямо.
- **Окно UAC.** На этом ПК запросы UAC отключены (по вашей просьбе). Поэтому ветка «пользователь нажал „Нет“ в окне UAC» проверена только тестом с подменой, вживую не проверялась.
- **Сбой мастера на реальных шагах** (нет сети, ошибка pip) проверен по коду и тестами. Вживую воспроизведён только успешный проход и автоматическая смена порта.
- **Установщик `PC-Control-Setup.exe` и `PC_Control_Windows.zip`** из релиза не пересобирались. Изменения попадут в них при следующей сборке релиза.
