# Окружение для тестирования и сравнительных бенчмарков

Данный документ содержит исчерпывающее описание аппаратного, программного и сетевого обеспечения, на котором проводились сравнительные измерения проектов **PC Control**, **Sunshine**, **RustDesk**, **KDE Connect** и **Moonlight Android**.

## 3. Сетевое окружение и параметры эмуляции

| Параметр | Значение | Описание |
|---|---|---|
| **Локальный loopback** | 127.0.0.1 (IPv4), `::1` (IPv6) | Замеры внутренней латентности IPC, сериализации, сокетов TCP и UDP. Задержка канала: < 0.1 мс. |
| **Локальная сеть (LAN)** | 1000BASE-T Ethernet / Wi-Fi 6 | Истинное межмашинное сетевое взаимодействие. Базовый пинг: 0.4–1.2 мс, джиттер < 0.2 мс. |
| **Сетевые сценарии (D)** | Синтетическая потеря 1%, 5%, 10% пакетов | Эмуляция задержек ретрансмиссий TCP (Head-of-Line blocking) против UDP с коррекцией ошибок Reed-Solomon FEC. |
| **Удалённые туннели** | Tailscale (WireGuard P2P), Cloudflare Tunnel | Тестирование механизма обхода NAT (STUN/TURN) и туннелирования портов. |

## 4. Ограничения окружения и их учёт

1. **Мобильные клиенты Android (Moonlight / KDE Connect)**:
   - В хостовой среде Windows 11 отсутствует подключённый по USB/Wi-Fi физический Android-смартфон с аппаратным декодером.
   - Поэтому клиентский декодинг Moonlight исследован на уровне исходного кода NDK (`MediaCodec`, `moonlight-common-c`), а серверная часть Moonlight (Sunshine) протестирована напрямую на аппаратном кодировщике RTX 3070 Ti.
2. **Безопасность системных вызовов**:
   - Операции выключения, перезагрузки и блокировки Windows (`ExitWindowsEx`, `LockWorkStation`) тестировались на уровне валидации формирования команд и прав доступа без фактического завершения хостовой сессии, чтобы не прерывать тестовый стенд.
3. **Строгая воспроизводимость**:
   - Для всех замеров использовались таймеры высокого разрешения `QueryPerformanceCounter` (`time.perf_counter_ns()` в Python с точностью до единиц наносекунд).
   - Все фоновые тяжёлые процессы (игры, компиляция) перед началом прогонов были отключены.
