# Перечень функций, не протестированных на физическом стенде

В соответствии с правилом строгой достоверности и запретом на выдумывание результатов («Не подставляй результаты вместо собственных измерений; неизмеренные показатели отмечай **«Не измерено»**»), ниже представлен полный перечень функций всех пяти проектов, которые не могли быть полноценно измерены на локальной рабочей станции Windows 11, с подробными техническими причинами и требованиями к окружению для будущих испытаний.

---

## 1. Функции Moonlight Android (Мобильный клиент)

| Функция | Статус | Причина невозможности локального замера | Минимальные требования для тестирования |
|---|---|---|---|
| **Аппаратное декодирование на Android (MediaCodec / SurfaceView)** | **Не измерено** | Тестовый хост работает под управлением Windows 11 x64. Декодирование кадров в `moonlight-android` осуществляется через вызов NDK `AMediaCodec_dequeueOutputBuffer` и рендеринг в `ANativeWindow`, что требует реального Android-устройства или физического ARM/x86 эмулятора с аппаратной поддержкой Vulkan/OpenGL ES. | Физический смартфон (Android 10+, чипсет Snapdragon 8 Gen 1/2/3 или MediaTek Dimensity) с экраном 120 Гц, подключённый по Wi-Fi 6 (5/6 ГГц) с поддержкой NDK. |
| **Сенсорный ввод и экранные стики Moonlight** | **Не измерено** | Входные события сенсорного экрана (`MotionEvent`) транслируются через внутренний класс `TouchController` приложения Android. На Windows-хосте отсутствует физический мультитач-экран с частотой опроса 240+ Гц. | Android-устройство с частотой дискретизации сенсора не менее 240 Гц, замер через Android debug bridge (`adb shell getevent`) и высокоскоростную камеру 240–1000 FPS. |
| **Вибрация и гироскоп геймпада (Haptic feedback / Gyro)** | **Не измерено** | Задействует Android API `Vibrator` и датчики движения Android для отправки телеметрии в Sunshine. В хостовой системе отсутствовал спаренный Android-клиент с активным датчиком IMU. | Android-клиент с контроллером (например, Razer Kishi или DualSense по Bluetooth) и акселерометром/гироскопом. |

## 2. Функции KDE Connect (Интеграция телефона и ПК)

| Функция | Статус | Причина невозможности локального замера | Минимальные требования для тестирования |
|---|---|---|---|
| **Приём и отправка SMS через телефон** | **Не измерено** | KDE Connect использует плагин `telephony` / `sms`, требующий активного сопряжения ПК с Android-телефоном, в который вставлена рабочая GSM/LTE SIM-карта с правами `READ_SMS` и `SEND_SMS`. | Смартфон с SIM-картой оператора связи, установленный KDE Connect Android из F-Droid/Play Store, спаренный с ПК в одной LAN. |
| **Синхронизация входящих звонков и уведомлений** | **Не измерено** | Плагин `notifications` перехватывает системные интенты Android `NotificationListenerService`. На хосте Windows 11 нет источника входящих сотовых вызовов. | Физический телефон под управлением Android с правами доступа к уведомлениям и активным сопряжением по TLS. |
| **Удалённый поиск телефона (Ring Phone)** | **Не измерено** | Инициирует отправку UDP/TCP пакета `kdeconnect.findmyphone.request` на телефон с включением аудиопотока `AudioManager.STREAM_ALARM`. Замер громкости и задержки срабатывания динамика требует физического устройства. | Телефон Android в режиме без звука, шумомер или микрофон для фиксации задержки звонка от момента клика на ПК. |
| **Виртуальный трекпад KDE Connect (Touchpad plugin)** | **Не измерено** | Приложение передаёт относительные смещения пальца по экрану через TLS-сокет. На локальном стенде замерен парсинг пакета JSON KDE Connect (4.1–4.4 мкс), но физический ввод с экрана смартфона не тестировался. | Смартфон с сенсорным экраном, высокоскоростной мониторинг пакетов через Wi-Fi точку доступа. |

## 3. Функции Sunshine (Сервер потокового видео)

| Функция | Статус | Причина невозможности локального замера | Минимальные требования для тестирования |
|---|---|---|---|
| **Эмуляция контроллеров Xbox 360 / DualShock 4 через ViGEmBus** | **Не измерено** | В тестовом окружении не был предустановлен низкоуровневый драйвер ядра `ViGEmBus` (`virtual gamepad bus driver`), необходимый Sunshine для создания виртуального XInput-устройства. | Установленный драйвер `ViGEmBus 1.21+` с цифровой подписью WHQL, права администратора для создания виртуальных узлов в диспетчере устройств. |
| **Передача HDR10 (10-бит PQ / SMPTE ST 2084)** | **Не измерено** | Монитор тестового стенда работает в режиме SDR (8-бит RGB). Активация захвата HDR DXGI (`DXGI_FORMAT_R10G10B10A2_UNORM`) требует HDR-совместимого дисплея и включения переключателя «Использовать HDR» в параметрах Windows 11. | Монитор с сертифицированным HDR (VESA DisplayHDR 600/1000), включённый HDR в настройках Windows 11, клиент с экраном OLED/HDR. |
| **Виртуальные дисплеи IddSampleDriver (Virtual Display Driver)** | **Не измерено** | Sunshine поддерживает создание фиктивных мониторов произвольного разрешения через драйвер непрямого отображения (IDD). Требует отдельной установки драйвера тестового режима Windows. | Драйвер IDD (например, `Virtual-Display-Driver`), сертификат для тестового режима Windows (`bcdedit /set testsigning on`). |

## 4. Функции RustDesk (Удалённый доступ и сервис)

| Функция | Статус | Причина невозможности локального замера | Минимальные требования для тестирования |
|---|---|---|---|
| **Маршрутизация через глобальные публичные серверы Rendezvous (HBBS/HBBR)** | **Не измерено** | Внешний доступ к публичным серверам RustDesk из изолированного тестового процесса может быть нестабилен из-за внешних географических задержек и ограничений сетевого шлюза. Замеры сетевого протокола проводились на изолированных сокетах. | Развёрнутая выделенная инфраструктура `hbbs` и `hbbr` на сервере с фиксированным публичным IP-адресом и задержкой RTT 10–30 мс. |
| **Служба Unattended Access (Windows Service)** | **Не измерено** | Установка RustDesk в качестве фоновой службы Windows (`RustDesk Windows Service`) требует повышения прав до `NT AUTHORITY\SYSTEM` и изменения системных сервисов хоста, что ограничено политикой безопасности стенда. | Изолированная виртуальная машина Hyper-V/VirtualBox с возможностью отката snapshot после инсталляции сервиса. |
| **Многомониторный режим с переключением экранов** | **Не измерено** | На рабочей станции подключён один физический монитор (DisplayPort 1920×1080). Функция переключения между экранами `display 1 / display 2` требует мультимониторной конфигурации. | Стенд с минимум двумя-тремя физическими мониторами, подключёнными к разным портам GPU (HDMI/DP). |
