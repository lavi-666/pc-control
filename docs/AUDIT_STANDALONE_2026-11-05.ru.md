# Проверка автономной установки и продолжение аудита — 5 ноября 2026

Основной результат этого этапа — работоспособный сценарий первого запуска без установленного пользователем Python. Подготовлены два варианта: полный Windows ZIP с частной средой выполнения и архив исходников, для которого настоящий Launcher.exe автоматически загружает и проверяет среду. Настройки выполняются через панель; ручное изменение config.json для проверенных сценариев не требовалось.

Этот документ дополняет `AUDIT_2026-11-05.ru.md`. Он не означает, что проверены все аппаратные функции, каждая модель телефона или чистая виртуальная Windows. Ниже разделены фактически выполненные проверки и ограничения.

**Устройство и упаковка проекта**

- `Launcher.exe` — загрузчик на C#, проверяет собственную панель, при необходимости показывает окно подготовки среды.
- `scripts/control_panel.py` и `web/control_panel.html` — локальная панель управления, HTTP API, настройки и управление процессами.
- `server.py`, `core`, `modules` — Flask API, авторизация, настройки, системные команды, медиа и потоковая передача.
- `scripts/watchdog.pyw` — наблюдение за сервером и восстановление после сбоя.
- `tools/streamer.exe` — отдельный компонент захвата экрана/звука; клиентские интерфейсы находятся в `web` и Android APK.
- `runtime` — переносимый CPython 3.12.16 и библиотеки; пользовательская установка Python не используется.
- `requirements-runtime.lock` фиксирует версии пакетов. `runtime-source.json` фиксирует источник Python и SHA-256. `build_runtime.py` создаёт среду из свежего дистрибутива, проверяет импорты и `pip check`.
- `package_windows.py` собирает полный архив без текущего config.json, журналов, SDK, ключей подписи и пользовательских сценариев. Архив проверяется по CRC; рядом записывается SHA-256.

**Как проводилась чистая установка**

1. Каждый запуск теста распаковывает новый архив в отдельную папку с пробелами и кириллицей под `scratch/Чистый ZIP ...`.
2. Полный архив содержит runtime, собранный из свежего скачивания Python и пакетов без кеша pip. Исходный архив создаётся из текущих файлов Git с локальными исправлениями, без игнорируемых runtime, venv и конфигурации разработчика.
3. Приложению передаётся PATH только с системными каталогами Windows. PYTHONHOME и PYTHONPATH намеренно указывают на несуществующие места, VIRTUAL_ENV и PC_REMOTE_TOKEN исключаются.
4. Запускается именно Launcher.exe с --no-browser; интерфейс затем открывает независимый драйвер Playwright в Edge. Python тестового драйвера не используется для выполнения панели или сервера.
5. Для исходного архива настоящий загрузчик показывает окно подготовки, скачивает Python, сверяет SHA-256, устанавливает пакеты без кеша и проверяет их. Этот путь несколько раз выявлял реальные ошибки bootstrap; после исправлений прошёл повторно.
6. Порт и пароль задаются через HTML-формы панели. Сервер запускается, перезапускается и останавливается через элементы интерфейса на отдельном порту.
7. Проверяются ответы конкретных HTTP-команд и отсутствие слушателя порта после остановки. Проверка не ограничивается текстом кнопки или временным значением индикатора.
8. Процесс панели завершается и запускается снова; порт, пароль и CORS должны восстановиться. Локальные тестовые процессы завершаются по точному пути этой копии.

Это изоляция установки и Python-зависимостей на существующей Windows, **не новая виртуальная машина**. Использовались имеющиеся Windows, Edge, системные библиотеки и драйверы. Отдельный тестовый интерпретатор управлял браузером. Существующая установка Tailscale могла определяться системой; установка Tailscale с нуля этим не проверена.

**Что ещё нельзя считать проверенным или завершённым**

- Физический телефон, установка APK, Android WebView, iOS/Safari, touch-жесты, работа в фоне и энергосбережение.
- Реальные WebRTC/WASAPI/DXGI-потоки между ПК и телефоном, длительная стабильность видео/аудио, микрофон, все медиаплееры и аппаратные конфигурации.
- Выключение, перезагрузка, сон, Wake-on-LAN после выключения, настройка BIOS/UEFI и внешний relay.
- Применение UAC, Windows Hello/автовхода, удаление правил firewall и полная деинсталляция. Для этих действий анализ кода и проверки ошибок не равны реальному end-to-end тесту.
- Перезагрузка чистой Windows VM, отсутствие системных VC-runtime/драйверов, антивирусные блокировки и ограниченные корпоративные политики.
- Длительные сбои сети во время bootstrap, отмена установки на каждом этапе, исчерпание диска и все варианты недоступности PyPI/GitHub.
- Полный сценарий обновления всего проекта. Существующий механизм обновляет Launcher.exe; он не является атомарным обновлением Python-кода, runtime и APK вместе.
- Межпроцессное одновременное редактирование config.json сервером и панелью: атомарная запись предотвращает обрыв файла, но не является полной транзакцией между независимыми процессами.
- При отсутствии Android SDK/исходников пересборка APK недоступна; обычному пользователю доступно готовое приложение. Одна проверка наличия SDK не гарантирует исправность каждой версии инструментария.
- Последние исправления проверены в локальных архивах. Соответствие уже опубликованного GitHub-релиза последнему локальному состоянию этим тестом не подтверждается.

Нельзя обоснованно заявить «каждая функция проекта проверена на ПК и телефоне» или «ошибок больше нет». Подтверждён автономный сценарий установки и основной цикл управления через лаунчер; аппаратная и внешняя интеграционная приёмка остаётся отдельной необходимой работой.

Повторная сверка после вопроса о полной настройке через лаунчер: Launcher.exe, control_panel.py и web/js/app.js совпадают с проверенным ZIP; текущий PC_Control.apk в рабочей папке уже отличается от APK внутри этого архива. Результаты приёмки относятся к архиву с указанной выше контрольной суммой. QR во встроенном пульте формирует ссылки для открытия веб-пульта с токеном и скачивания APK; это не подтверждение физической связи с телефоном и не автоматическая передача настроек в установленное Android-приложение.
