# Полное обновление через лаунчер

Пользователь открывает Launcher.exe и нажимает «Проверить обновления», затем «Обновить сейчас». Ручная замена файлов, запуск команд и установка Python не нужны. При запуске лаунчер также проверяет наличие обновления.

## Что обновляется

Обновляется весь распространяемый пакет: Launcher.exe, сервер, панель, модули, веб-интерфейс, вспомогательные скрипты, инструменты, встроенный Python и библиотеки, файл Android APK. Установка APK на самом телефоне остаётся отдельным действием пользователя.

Сравниваются SHA-256 файлов и идентификатор сборки, а не только номер версии. Даже изменение одного распространяемого файла или новый опубликованный commit вызывает предложение обновиться. Изменения на GitHub становятся доступны после успешной сборки и публикации релиза; неопубликованный код из ветки не устанавливается.

Полный архив скачивается и проверяется целиком, но заменяются только изменённые файлы. Отсутствующие файлы восстанавливаются, удалённые из нового манифеста файлы предыдущей поставки удаляются. Произвольные пользовательские файлы не очищаются. Локальные правки поставляемого исходного кода заменяются официальными файлами.

## Сохранение данных и восстановление

config.json, launch_presets.json, журналы и другие файлы вне манифеста не заменяются. Это сохраняет настройки, токены и привязки, хранящиеся в пользовательской конфигурации. Обновление останавливает процессы только своей установки; ранее работающий сервер запускается снова.

Установщик работает из отдельной копии текущего Python. До изменения файлов сохраняется план операции, заменяемые файлы перемещаются в резервную копию. После установки проверяются загрузка Launcher.exe, ответ панели своей установки, импорт основных библиотек и запуск сервера, если он работал до обновления. Ошибка вызывает откат. После прерывания повторный запуск Launcher.exe выполняет восстановление. Не удаляйте соседнюю папку `.pccontrol-update-*`, пока операция не закончена: она нужна для восстановления. Старые завершённые операции очищаются при следующих обновлениях; последняя резервная копия сохраняется.

Нужны доступ к GitHub и минимум 3 ГБ свободного места. Для больших архивов дополнительно проверяется запас относительно распакованного размера. Повреждённый архив, несовпадающие хеши, недопустимые пути и попытки заменить пользовательскую конфигурацию отклоняются.

## Публикация

Релиз должен содержать `PC_Control_Windows.zip`, `release-manifest.json`, `SHA256SUMS.txt`. Workflow настроен на сборку и публикацию при push в main, а также по тегу и ручному запуску. Старый релиз без этих файлов выдаёт понятную ошибку вместо частичной замены Launcher.exe.

Новый механизм реализован в локальном проекте. Публикация этой реализации в GitHub из данного чата не выполнялась. Старые установленные лаунчеры с прежним механизмом обновления не получают новую логику автоматически до установки обновлённого лаунчера/пакета.

## Проверка

Автоматические проверки находятся в `tests/test_update_system.py`. Практический сценарий `tests/audit_full_update.py` использует настоящий Launcher.exe, браузерную кнопку, отдельные процессы Windows и полный ZIP. Сетевой источник заменён локальным релизом для воспроизводимости; установка, проверка запуска и откат выполняются настоящим кодом.

Проверяются успешное обновление всех хешей, удаление устаревшего файла, сохранение настроек и работающего сервера; откат пакета с неисправным запуском; восстановление прерванной замены через Launcher.exe. Это не проверка живой публикации GitHub, физического отключения питания или установки APK на телефоне.
