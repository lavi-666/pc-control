# Аудит PC Control — 5 ноября 2026

## Результат и границы

Выполнены анализ компонентов проекта, исправления, автоматизированные HTTP/API и браузерные проверки, проверки сборки и испытание полного Windows-архива после распаковки без пользовательской конфигурации.

**Это не подтверждение безошибочности каждой функции на каждом устройстве.** Физический Android/iOS, полноценная новая установка Windows, изменения Windows Hello/автовхода и реальные сквозные медиапотоки не проверены. Для этих пунктов ниже указаны ограничения. Проверки имитации системных действий не считаются проверками оборудования.

Рабочая папка изначально содержала изменения пользователя. В процессе появились новые коммиты, включая Release/SHA-256 updater и упаковку дистрибутива; они сохранены, итоговые проверки выполнены по обновлённым исходникам. Последняя зафиксированная основа — `be0865a`; отчёт также охватывает последующие локальные изменения. Коммиты, публикацию релиза и развёртывание в GitHub из этого аудита не выполняли.

Полную замену установленного приложения через внешний релиз не выполняли.

Большой набор выполнялся в `scratch/audit-project` с перенаправлением всех тестовых запросов на отдельный случайный порт. Вызовы выключения/сна/изменения системной громкости работали в тестовом режиме. WOL проверяет отправку пакетов и формат ответов, а не фактическое включение выключенного ПК.

**Качество старого набора ограничено:** некоторые тесты считают отсутствие аудиоустройства или исключение допустимым успехом, некоторые принимают HTTP 500, часть пунктов проверяет лишь структуру ответа. Поэтому 649/650 нельзя трактовать как 649 проверенных аппаратных функций или процент покрытия исходников.

## Чистая установка: что именно проверено

Полный ZIP создан из явного списка runtime-файлов. В нём нет текущего config.json, журналов, venv, .git, Android SDK, ключа подписи и пользовательских сценариев; `launch_presets.json` содержит пустой список. Архив прошёл CRC-проверку, рядом создан SHA-256-файл.

Архив распакован в `scratch/clean-package-audit/PC_Control`. До первого обращения config.json отсутствовал. Панель создала его, браузерные тесты сохранили адрес ретранслятора, пароль, CORS и язык, проверили повторную загрузку и возврат сохранённого значения. Затем сервер реально запущен, перезапущен и остановлен через функции панели на отдельном порту.

Использовались существующая Windows и отдельный подготовленный Python venv. Это **не** испытание на новой виртуальной Windows без Python, браузера, драйверов и прав пользователя. Автоматическая установка Python/winget и Windows UAC в чистой ОС остаются непроверенными.

## Непроверенное и оставшиеся ограничения

1. Нет подключённого физического телефона и Android-эмулятора/adb в доступном SDK. APK не устанавливался; touch-жесты, WebView конкретной версии, фоновые ограничения Android, уведомления, Bluetooth, iOS/Safari не проверялись.
2. Панель управления привязана к loopback и предназначена для компьютера. На телефоне используется веб-пульт или APK. Узкая вёрстка панели проверена, но доступ к ней по LAN не включался.
3. Не выполнялись реальные выключение, сон, перезагрузка Windows, Windows Hello, netplwiz/автовход и изменение firewall. Для этих кнопок анализировались обработчики/ответы; отдельные ошибки проверялись с подменой исполнителя. Их нельзя считать end-to-end проверенными.
4. Не подтверждены реальные WebRTC/WASAPI/DXGI-потоки от ПК до телефона, отсутствие рассинхронизации звука, работа микрофона, всех медиаплееров и браузерных UIA-интеграций. Не было многочасового аппаратного stress-теста.
5. Не проверено включение выключенного компьютера через телефонный Termux/Tailscale relay, настройки BIOS/UEFI, сетевой карты и роутера. Установка Termux/relay по-прежнему требует действий вне Windows-лаунчера.
6. Не выполнено аварийное зависание сервера с полным испытанием восстановления watchdog. Проверены запуск/остановка и кодовые защитные исправления.
7. Текущий updater обновляет Launcher.exe. Это не транзакционное обновление Python, HTML, Rust-компонента и APK из полного ZIP. Полный автоматический upgrade/rollback всей установки остаётся отдельной задачей. ZIP подготовлен локально; его публикация и запуск GitHub Actions в рамках аудита не выполнялись.
8. APK-пересборка требует Android SDK/JDK; автоматического скачивания всего SDK через панель нет. При отсутствии инструментов теперь показывается ошибка, а не ложный успех. Обычному пользователю предоставляется уже собранный APK.
9. Блокировки конфигурации защищают операции внутри процесса, но не являются полноценными межпроцессными транзакциями. Одновременные изменения из нескольких процессов требуют отдельного stress-теста и при необходимости общего файлового lock-механизма.
10. Ошибки повреждённого существующего config.json, гарантированное восстановление всех вариантов старых конфигураций и полный импорт/экспорт настроек не покрыты. «Вернуть сохранённые» отменяет несохранённые изменения формы, а не выполняет глобальный factory reset.
11. Не проводился построчный формальный аудит каждого исходника и нет измеренного полного branch coverage. Проведены широкие автоматизированные проверки и целевой анализ компонентов; отсутствие найденной ошибки не означает доказанную исправность.

## Файлы результата и воспроизводимость

- `dist/PC_Control_Windows.zip` — полный пакет для распаковки и запуска Launcher.exe.
- `dist/PC_Control_Windows.zip.sha256` — контрольная сумма архива.
- `Launcher.exe`, `PC_Control.apk` — актуальные бинарники рабочей папки.
- `scratch/Launcher.before-audit.exe`, `scratch/PC_Control.before-audit.apk` и `.idsig` — резервные копии до пересборки в первой части аудита.
- `tests/test_launcher_audit.py`, `tests/test_server_audit.py`, `tests/test_distribution_audit.py` — новые регрессии.
- `tests/audit_browser.py`, `tests/audit_remote_browser.py` — браузерные сценарии; Playwright используется только в тестовом окружении.
- `scratch/audit-project/scratch/suite-results.json` — результаты большого прогона.
- `scratch/audit-project/scratch/final-unit-tests.log` — журнал финальных unit/integration тестов.
- `scratch/clean-package-audit/PC_Control/scratch/panel-*.png` — скриншоты панели из чистого архива.

Для повторения тестов, меняющих конфигурацию и создающих процессы, использовать отдельную копию проекта. Не запускать старый `run_all_650_tests.py` против рабочего сервера: его адрес по умолчанию фиксирован, а часть сценариев меняет состояние сервера.

Рекомендуемый следующий этап приёмки — физический Android и отдельная Windows VM: первая установка без Python, реальные UAC/автовход/firewall, длительное аудио/видео, WOL после выключения и обновление полного приложения с сохранением настроек.
